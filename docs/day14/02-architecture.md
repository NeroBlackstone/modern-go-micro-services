## 启动流程

```
1. Vault Server 启动（Dev Mode，使用 VAULT_TOKEN 直接认证）
   │
2. vault-init 容器启动
   │  ├── 启用 KV v2 引擎
   │  ├── 写入所有密钥
   │  └── 列出已写入的密钥路径
   │
3. 服务启动（book-service 为例）
   │  ├── 读取本地 YAML 配置
   │  ├── 连接 Vault（VAULT_TOKEN 认证）
   │  ├── 从 Vault 读取密钥
   │  │     ├── secret/data/database/book
   │  │     └── secret/data/service-auth
   │  ├── 用 Vault 密钥覆盖本地配置
   │  └── 使用覆盖后的配置初始化组件
   │
4. 服务正常运行
```

## 策略设计（最小权限 — 生产环境目标）

> **当前实现（Dev 模式）：** 所有服务共用 `VAULT_TOKEN=my-root-token`，拥有全部权限。
> 以下策略设计是生产环境的目标方案，可通过 AppRole 认证实现。

```
book-service 策略：
┌─────────────────────────────────┐
│ path "secret/data/database/book"│  ✓ 可读
│ path "secret/data/service-auth" │  ✓ 可读
│ path "secret/data/jwt"          │  ✓ 可读
│ path "secret/data/database/order"│ ✗ 不可读
│ path "secret/data/rabbitmq"     │  ✗ 不可读
└─────────────────────────────────┘

order-service 策略：
┌──────────────────────────────────┐
│ path "secret/data/database/order"│  ✓ 可读
│ path "secret/data/rabbitmq"      │  ✓ 可读
│ path "secret/data/jwt"           │  ✓ 可读
│ path "secret/data/service-auth"  │  ✓ 可读
│ path "secret/data/database/book" │  ✗ 不可读
└──────────────────────────────────┘

admin-service 策略：
┌──────────────────────────────────┐
│ path "secret/data/database/order"│  ✓ 可读（与 order 共享 DB）
│ path "secret/data/rabbitmq"      │  ✓ 可读
│ path "secret/data/jwt"           │  ✓ 可读
│ path "secret/data/service-auth"  │  ✗ 不可读（admin 不做服务间调用）
└──────────────────────────────────┘
```

## 与现有架构的集成点

```
Traefik → Oathkeeper → 后端服务
                         │
                    ┌────▼────┐
                    │ Vault   │ ← 服务启动时连接
                    │ Client  │
                    └────┬────┘
                         │
              ┌──────────┼──────────┐
              │          │          │
         ┌────▼───┐ ┌───▼────┐ ┌──▼──────┐
         │Postgres │ │RabbitMQ│ │JWT Secret│
         │ (密码)  │ │ (密码) │ │ (签名)  │
         └────────┘ └────────┘ └─────────┘
```

Vault 作为**启动时的密钥提供者**，不影响运行时的请求处理路径：

- **不影响性能**：密钥只在启动时读取一次，运行时使用内存中的值
- **不影响现有流程**：Oathkeeper、gRPC 拦截器等保持不变
- **可选依赖**：Vault 不可用时服务仍能正常启动

## 与 Day 13 的关系

```
Day 13: 服务间认证（Shared Secret JWT）
         ↓
Day 14: 密钥管理（Vault）
         │
         ├── 之前：shared_secret 写在 YAML / 环境变量默认值
         ├── 现在：shared_secret 存在 Vault 中，服务启动时读取
         └── 效果：密钥不再硬编码，支持审计和轮换
```
