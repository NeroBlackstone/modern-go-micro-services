# Day 11 - OAuth2 / OpenID Connect 概念

## 为什么需要 OAuth2？

在 Day 10 中，我们搭建了基于 Kratos + Oathkeeper 的内部认证系统。这个系统解决了**内部用户**的认证问题，但有一个局限：

```
内部用户（浏览器）：
┌─────────────┐      ┌─────────────┐      ┌─────────────┐
│   浏览器    │ ──── │  Kratos     │ ──── │  Oathkeeper │
│  (Cookie)   │      │  (Session)  │      │  (验证)     │
└─────────────┘      └─────────────┘      └─────────────┘

外部应用（第三方）：
┌─────────────┐      ┌─────────────┐
│  第三方应用  │ ──── │  ???        │  ← 没有认证机制！
│  (无Session) │      │             │
└─────────────┘      └─────────────┘
```

**问题**：当外部应用（如移动端、第三方服务）需要访问你的 API 时：
1. 它们没有 Kratos Session Cookie
2. 你不能把 Kratos 的密码告诉它们
3. 你需要一种标准化的授权机制

**OAuth2 就是为了解决这个问题**：让第三方应用在**不获取用户密码**的情况下，获得有限的访问权限。

## OAuth2 核心概念

### 四种授权模式

```
┌─────────────────────────────────────────────────────────────┐
│                    OAuth2 授权模式                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Authorization Code（授权码模式）                         │
│     ✅ 最安全，推荐用于 Web 应用                             │
│     流程：授权码 → 用 code 换 token                         │
│                                                             │
│  2. Client Credentials（客户端凭证模式）                     │
│     ✅ 适合机器对机器（M2M）通信                             │
│     流程：直接用 client_id + secret 换 token                │
│                                                             │
│  3. Implicit（隐式模式）                                     │
│     ⚠️  已不推荐，安全性差                                   │
│     流程：直接返回 token（无 code 交换）                     │
│                                                             │
│  4. Resource Owner Password（密码模式）                      │
│     ⚠️  已不推荐，需要用户密码                               │
│     流程：用用户名 + 密码直接换 token                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 核心角色

| 角色 | 说明 | 本项目对应 |
|------|------|-----------|
| **Resource Owner** | 资源所有者（用户） | 浏览器用户 |
| **Client** | 第三方应用 | `oauth-client-demo` |
| **Authorization Server** | 授权服务器 | Ory Hydra |
| **Resource Server** | 资源服务器（API） | user-service, order-service |

### 核心流程（Authorization Code）

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  用户    │     │  Client  │     │  Hydra   │     │  Kratos  │
│ (浏览器) │     │ (第三方) │     │ (授权)   │     │ (身份)   │
└────┬─────┘     └────┬─────┘     └────┬─────┘     └────┬─────┘
     │                │                │                │
     │  1. 点击登录   │                │                │
     │ ──────────────>│                │                │
     │                │                │                │
     │                │ 2. 重定向到 Hydra                │
     │ <──────────────│ ──────────────>│                │
     │                │                │                │
     │                │                │ 3. 检查登录状态 │
     │                │                │ ──────────────>│
     │                │                │ <──────────────│
     │                │                │                │
     │                │                │ 4. 返回登录页  │
     │ <───────────────────────────────│                │
     │                │                │                │
     │ 5. 用户登录    │                │                │
     │ ────────────────────────────────────────────────>│
     │                │                │                │
     │                │                │ 6. 验证通过    │
     │ <───────────────────────────────────────────────│
     │                │                │                │
     │                │                │ 7. 请求同意    │
     │ <───────────────────────────────│                │
     │                │                │                │
     │ 8. 同意授权    │                │                │
     │ ────────────────────────────────>│                │
     │                │                │                │
     │                │ 9. 返回 authorization_code      │
     │ <──────────────│ <──────────────│                │
     │                │                │                │
     │                │ 10. 用 code 换 token            │
     │                │ ──────────────>│                │

     │                │                │                │
     │                │ 12. 用 token 访问 API           │
     │                │ ───────────────────────────────>│
     │                │                │                │
```

### Token 类型

#### Access Token
- **用途**：访问受保护的资源（API）
- **特点**：有过期时间，通常较短（1小时）
- **格式**：JWT 或 Opaque

#### Refresh Token
- **用途**：获取新的 Access Token
- **特点**：有效期较长（30天），仅用于续期
- **安全**：必须安全存储，不能暴露给前端

#### ID Token (OpenID Connect)
- **用途**：证明用户身份
- **特点**：包含用户信息（claims）
- **格式**：JWT

## OpenID Connect (OIDC)

OIDC 是在 OAuth2 之上的**身份层**，增加了：

1. **标准化的用户信息**：`sub`, `email`, `name` 等
2. **Discovery 端点**：`/.well-known/openid-configuration`
3. **ID Token**：JWT 格式的身份证明

```
OAuth2:  "我可以访问你的资源"
OIDC:    "我是谁（身份信息） + 我可以访问你的资源"
```

## 与 Day 10 的关系

```
Day 10（内部认证）：
  Kratos → Oathkeeper → 后端服务
  (Cookie Session)

Day 11（外部认证）：
  外部应用 → Hydra → Kratos（用户登录）
                  → 签发 token
                  → 后端服务（验证 token）
```

**关键区别**：
- Day 10：用户通过浏览器 Cookie 认证
- Day 11：外部应用通过 OAuth2 Token 认证
